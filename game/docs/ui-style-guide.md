# UI 视觉规则

## 整体定位

视觉方向是：企业决策终端 + 航天器仪表 + 情报分析系统。

界面气质应当简洁、典雅、克制、有技术感、低美术依赖。它不应该像批量生成的 AIGC 科幻后台，也不应该靠装饰图、霓虹渐变或随机图表制造“未来感”。

## 信息层级

桌面端建议布局：

- 顶部全局状态栏：只放日期、暂停/倍速、现金与 runway、当前关键任务、警报数量。
- 左侧主导航：切换公司、研发、数据、算力、评估、发布等主视图。
- 中央工作区：承载当前决策、评估报告、任务安排和主要表格。
- 右侧上下文/任务/事件面板：显示当前行动说明、风险、任务队列、警报和自动暂停原因。
- 底部时间线或状态条：显示任务持续时间、发布窗口、季度结算点和关键事件。

在 1280px 左右宽度时，右侧面板可以收为抽屉。1280x720 仍必须能完成核心操作，不能依赖大屏才能找到关键按钮。

不要把所有资源都塞进顶栏。顶栏是全局态势，不是资源总账。

## 字体

- 长中文正文使用系统中文无衬线字体。
- 数字、日期、代码、状态 ID、任务编号和短状态标签使用等宽字体。
- 不要让长中文段落全部使用等宽字体。
- 中文是主语言，英文只作为技术术语或次级标签。
- 字号按信息密度设定，面板内标题不能使用英雄区尺度的大字。

## 颜色

初始 token 使用低饱和、低眩光方案。以下 hex 是建议值，之后允许人工微调。

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `canvas` | 页面底色，接近黑色 | `#0B0D0E` |
| `surface` | 主面板炭灰 | `#151819` |
| `surfaceRaised` | 稍亮的浮起区域 | `#1D2224` |
| `borderSubtle` | 低对比细边框 | `#2A3033` |
| `textPrimary` | 暖灰白正文 | `#E3DED5` |
| `textSecondary` | 灰色辅助文字 | `#9A9A93` |
| `danger` | 克制的红色 | `#C85C5C` |
| `warning` | 琥珀色警告 | `#C9984A` |
| `success` | 低饱和绿色 | `#6FA178` |
| `focus` | 清晰 keyboard focus | `#8AB4F8` |

状态色只能辅助识别，不能成为唯一信息来源。风险等级必须同时有文字、图标、符号或排序。

## 形状与间距

- 边框以 1px 为主。
- 圆角只允许 0、2、4px 级别。
- 不使用大面积投影；层级主要靠边框、明度和布局区隔。
- 使用稳定的 4/8px 间距体系。
- 工具栏、状态栏、表格行高、任务条和图表轴线需要稳定尺寸，不能因 hover 或数字变化跳动。
- 装饰线、网格、角标必须承担分区、对齐或状态含义，不能只是填空。

## 图形

图形必须来自真实游戏状态。没有状态来源时，不画图。

首版优先图形：

- 对齐的能力条。
- benchmark 表。
- 小型趋势线。
- 任务时间线。
- 风险列表或矩阵。

雷达图只能作为候选概览，不能作为主要比较工具。

图形实现优先 CSS 和 SVG。不展示无含义的随机波形、代码雨、地图、数字和图表。不使用假数据制造“科技感”。不需要 3D 地球，也不需要 AI 概念图。

## 动效

动效只表达暂停、任务开始、任务完成、警告和状态变化。

普通动效保持短促，避免拖慢操作反馈。不使用持续漂浮、呼吸发光和大面积粒子。

CRT 扫描线只能非常弱，并且必须可以关闭。扫描线不得覆盖或影响正文阅读。

## 无障碍和可用性

- 键盘 focus 必须可见。
- 不能只靠颜色表达风险。
- 数字变化要有文本或符号说明，例如上升、下降、减少 runway、警报新增。
- 保证中文可读性，长段落保持合理行宽。
- 1440x900 是主要设计尺寸。
- 1280x720 必须仍可操作。
- 第一版不以移动端作为目标。
- 高频操作按钮需要位置稳定，不能在结算、警报或面板展开时突然移动到远处。

## 明确禁止

- 玻璃拟态。
- 彩色霓虹渐变。
- 巨大圆角卡片。
- 泛滥的 glow。
- 通用 SaaS dashboard 模板感。
- 无意义英文标题。
- 每个面板都配一张装饰图。
- AI 生成角色立绘和科技背景。
- 为了“未来感”牺牲信息密度。
- 完美对称但缺少操作优先级的卡片网格。
- 参考截图中的截图、logo、文字或资产进入仓库。
